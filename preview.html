React useDeferredValue Hook Kya Hai (in Hindi)

Category: ReactJS

React useDeferredValue Hook kya hai? Is Hindi guide me slow rendering aur UI lag ko fix karne ka tarika code implementation ke sath seekhein.

तो मेरे डेवलपर दोस्तों, क्या आपने कभी ऐसा महसूस किया है कि जब आप अपने React components में किसी heavy search input पर तेज़ी से टाइप करते हैं, तो आपका कीबोर्ड और इनपुट फील्ड दोनों अटकने (lag होने) लगते हैं? ऐसा इसलिए होता है क्योंकि React हर एक कीस्ट्रोक पर पूरी भारी-भरकम लिस्ट को दोबारा रेंडर करने की कोशिश करता है, जिससे ब्राउज़र का मेन थ्रेड ब्लॉक हो जाता है। इसी सिरदर्द को हमेशा के लिए खत्म करने के लिए React 18 में एक चमत्कारी हुक पेश किया गया था, जिसका नाम है useDeferredValue Hook।

⚡ Quick Answer: React useDeferredValue Hook React 18 का एक powerful performance optimization hook है जो UI के heavy rendering updates को defer (postpone) करता है। जब state तेज़ी से बदलती है, तो यह main status update को block किए बिना background में process करता है, जिससे UI lag-free और responsive बनी रहती है।

React useDeferredValue Hook क्या है और इसकी जरूरत क्यों पड़ी?

सरल शब्दों में कहें तो, useDeferredValue Hook हमें किसी भी value के अपडेट को "non-urgent" (कम जरूरी) घोषित करने की अनुमति देता है। इसका मतलब यह है कि जब यूजर इनपुट में कुछ लिखता है, तो नया इनपुट तुरंत स्क्रीन पर दिखना चाहिए (यह urgent है), लेकिन उस इनपुट के आधार पर नीचे रेंडर होने वाली बड़ी लिस्ट थोड़ा रुक कर भी अपडेट होगी तो चलेगा (यह non-urgent है)।

React 18 से पहले, जब भी हम किसी ReactJS एप्लीकेशन में स्टेट को अपडेट करते थे, तो React उसे तुरंत रेंडर करने की कोशिश करता था। इसे "Synchronous Rendering" कहते हैं। अगर आपके पेज पर कोई ऐसा कंपोनेंट है जो रेंडर होने में 200ms का समय लेता है, और यूजर हर 50ms में कीबोर्ड का बटन दबा रहा है, तो ब्राउज़र का मेन थ्रेड चोक हो जाएगा। इसी समस्या को सुलझाने के लिए Concurrent Rendering का कांसेप्ट लाया गया, जिसके अंतर्गत useDeferredValue Hook काम करता है।

useDeferredValue Hook कैसे काम करता है?

ध्यान देने वाली बात ये है कि useDeferredValue कोई नया स्टेट नहीं बनाता है, बल्कि यह आपकी मौजूदा स्टेट की एक "deferred copy" यानी कि एक धीमी कॉपी तैयार करता है।

जब भी आपकी असली स्टेट बदलती है, तो React तुरंत नए वैल्यू के साथ पहला रेंडर चलाता है (urgent update)। इस रेंडर के दौरान, useDeferredValue से मिलने वाली वैल्यू पुरानी ही रहती है। इसके तुरंत बाद, React बैकग्राउंड में एक दूसरा रेंडर शुरू करता है जिसमें deferred value को नई वैल्यू के साथ अपडेट कर दिया जाता है (non-urgent update)।

अगर बैकग्राउंड रेंडरिंग के दौरान यूजर फिर से कोई नया बटन दबा देता है, तो React समझदारी दिखाते हुए पुराने बैकग्राउंड रेंडर को बीच में ही छोड़ (abort) देता है और नए यूजर इनपुट को प्रायोरिटी देता है। यही कारण है कि आपका UI कभी भी हैंग या फ्रीज नहीं होता।

React useDeferredValue Hook का Syntax

इसका सिंटैक्स बेहद आसान और सीधा है। आपको बस अपनी उस स्टेट को इस हुक के अंदर पास करना होता है जिसे आप धीमा करना चाहते हैं:

import { useState, useDeferredValue } from 'react';

function MyComponent() {
  const [text, setText] = useState("");
  
  // text की deferred copy तैयार करना
  const deferredText = useDeferredValue(text);

  return (
    <div>
      <input value={text} onChange={e => setText(e.target.value)} />
      <HeavyList text={deferredText} />
    </div>
  );
}

यहाँ पर ध्यान दें कि हमने <input> के value attribute में text (original state) का इस्तेमाल किया है ताकि टाइपिंग एकदम स्मूथ रहे, और <HeavyList> को हमने deferredText भेजा है ताकि वह बैकग्राउंड में शांति से रेंडर हो सके।

Production-Ready complete Code Example

चलिए, एक पूरा और वर्किंग कोड लिखकर देखते हैं। हम एक ऐसी एप्लीकेशन बनाएंगे जिसमें एक सर्च इनपुट होगा और 5000 आइटम्स की एक बहुत बड़ी लिस्ट होगी। हम देखेंगे कि कैसे useDeferredValue हमारे UI को सुपर-फास्ट बना देता है।

सबसे पहले, एक फ़ाइल बनाएं जिसका नाम HeavyList.jsx होगा। इस कंपोनेंट को ध्यान से देखें, हमने यहाँ पर React.memo का इस्तेमाल किया है। यह बहुत महत्वपूर्ण है, जिसके बारे में हम आगे चर्चा करेंगे।

import React, { useMemo } from 'react';

// React.memo का उपयोग करना अनिवार्य है ताकि फालतू रेंडरिंग न हो
const HeavyList = React.memo(({ query }) => {
  // 10,000 डमी आइटम्स बनाना जो CPU पर भारी पड़ें
  const items = useMemo(() => {
    const list = [];
    for (let i = 0; i < 10000; i++) {
      list.push(`Item Number #${i + 1}`);
    }
    return list;
  }, []);

  // डमी आइटम्स को यूजर के इनपुट (query) के आधार पर फ़िल्टर करना
  const filteredItems = useMemo(() => {
    if (!query) return items;
    return items.filter(item => item.toLowerCase().includes(query.toLowerCase()));
  }, [query, items]);

  return (
    <ul style={{ 
      maxHeight: '300px', 
      overflowY: 'scroll', 
      border: '1px solid #ccc', 
      padding: '10px',
      borderRadius: '8px',
      marginTop: '15px'
    }}>
      {filteredItems.map((item, index) => (
        <li key={index} style={{ padding: '5px 0', borderBottom: '1px solid #eee' }}>
          {item}
        </li>
      ))}
      {filteredItems.length === 0 && <li>कोई मैच नहीं मिला!</li>}
    </ul>
  );
});

HeavyList.displayName = 'HeavyList';

export default HeavyList;

अब हम अपना मुख्य कंपोनेंट यानी App.jsx बनाएंगे, जहाँ पर हम इस HeavyList का उपयोग करेंगे और useDeferredValue की जादुई ताकत को देखेंगे।

import { useState, useDeferredValue } from 'react';
import HeavyList from './HeavyList';

export default function App() {
  const [searchTerm, setSearchTerm] = useState('');
  
  // यहाँ पर useDeferredValue का जादू शुरू होता है
  const deferredSearchTerm = useDeferredValue(searchTerm);

  // यह चेक करने के लिए कि क्या रेंडरिंग अभी भी बैकग्राउंड में पेंडिंग है
  const isStale = searchTerm !== deferredSearchTerm;

  return (
    <div style={{ maxWidth: '500px', margin: '40px auto', fontFamily: 'sans-serif', padding: '20px' }}>
      <h2>React useDeferredValue Demo</h2>
      <p>नीचे दिए गए इनपुट में तेज़ी से टाइप करके देखें, आपका इनपुट बिल्कुल भी लैग नहीं करेगा!</p>
      
      <input
        type="text"
        placeholder="यहाँ टाइप करें (e.g., #1000)..."
        value={searchTerm}
        onChange={(e) => setSearchTerm(e.target.value)}
        style={{
          width: '100%',
          padding: '12px 16px',
          fontSize: '16px',
          borderRadius: '8px',
          border: '2px solid #2563eb',
          outline: 'none',
          boxSizing: 'border-box'
        }}
      />

      {/* अगर बैकग्राउंड में लिस्ट रेंडर हो रही है, तो हम यूजर को इंडिकेशन दे सकते हैं */}
      <div style={{
        marginTop: '10px',
        fontSize: '14px',
        color: '#6b7280',
        transition: 'opacity 0.2s',
        opacity: isStale ? 0.5 : 1
      }}>
        {isStale ? "बैकग्राउंड में लिस्ट अपडेट हो रही है..." : "अप-टू-डेट"}
      </div>

      <HeavyList query={deferredSearchTerm} />
    </div>
  );
}

useDeferredValue vs Debounce vs Throttle: क्या अंतर है?

बहुत से डेवलपर्स को यह कन्फ्यूजन रहता है कि जब हमारे पास पहले से ही Debounce और Throttle जैसी तकनीकें हैं, तो फिर useDeferredValue की क्या जरूरत है? तो चलिए इस अंतर को एक साफ़ टेबल के जरिए समझते हैं:

विशेषता (Feature) useDeferredValue Debouncing Throttling
समय सीमा (Timing) ब्राउज़र के थ्रेड फ्री होने पर तुरंत चलता है (No fixed delay)। एक निश्चित समय (e.g., 300ms) तक रुकने के बाद चलता है। एक निश्चित अंतराल (e.g., 200ms) पर लगातार चलता रहता है।
User Experience सुपर स्मूथ, जैसे ही मशीन फ्री होगी UI अपडेट हो जाएगा। यूजर को टाइपिंग बंद करने के बाद थोड़ा इंतजार करना पड़ता है। लगातार हैंग-फ्री अनुभव देने की कोशिश करता है लेकिन लैग हो सकता है।
API Calls सिर्फ Local UI Rendering और CPU heavy tasks के लिए सही है। Network / API calls को कम करने के लिए सबसे बेस्ट है। Scroll event या Resize event को हैंडल करने के लिए बेस्ट है।

useDeferredValue vs useTransition: कौन सा कब इस्तेमाल करें?

यह भी एक बहुत ही कॉमन इंटरव्यू क्वेश्चन है। दोनों ही हुक्स React 18 के Concurrent features का हिस्सा हैं और रेंडरिंग को ऑप्टिमाइज़ करते हैं, लेकिन दोनों के काम करने का तरीका अलग है:

  • useTransition: इसका उपयोग तब किया जाता है जब आपके पास स्टेट अपडेट करने वाला फंक्शन (जैसे setSearchTerm) उपलब्ध होता है। आप अपने स्टेट चेंज करने वाले कोड को startTransition(() => { ... }) के अंदर रैप करते हैं।
  • useDeferredValue: इसका उपयोग तब किया जाता है जब आपके पास सिर्फ एक वैल्यू होती है, जो आपको शायद किसी पैरेंट कंपोनेंट या थर्ड-पार्टी लाइब्रेरी से props के रूप में मिल रही हो, और आपका सीधे स्टेट अपडेटर फंक्शन पर कोई कंट्रोल न हो।

अधिक जानकारी और कोर कांसेप्ट को गहराई से समझने के लिए आप Official React Docs को भी पढ़ सकते हैं।

useDeferredValue का use करते समय होने वाली Common Errors और उन्हें कैसे सुधारें?

दोस्तों, इस हुक का इस्तेमाल करते समय कई नए और यहाँ तक कि अनुभवी डेवलपर्स भी कुछ बड़ी गलतियां कर बैठते हैं जिससे उनकी एप्लीकेशन में अजीब सा बिहेवियर या error देखने को मिलता है। चलिए उन पर नज़र डालते हैं ताकि आप उन गलतियों से बच सकें:

1. Child Component को Memoize न करना (The Biggest Mistake)

अगर आपने पैरेंट कंपोनेंट में useDeferredValue का उपयोग किया है, लेकिन जिस चाइल्ड कंपोनेंट को आप वह वैल्यू भेज रहे हैं उसे React.memo से रैप नहीं किया है, तो आपका ऑप्टिमाइज़ेशन बिल्कुल बेकार चला जाएगा! क्योंकि हर इनपुट चेंज पर पैरेंट फिर से रेंडर होगा और बिना मेमोइजेशन के चाइल्ड भी दोबारा रेंडर होने लगेगा।

समाधान: हमेशा अपने चाइल्ड कंपोनेंट को React.memo से सुरक्षित करें जैसा कि हमने ऊपर कोड एग्जांपल में किया है।

2. Dynamic Object Reference को Pass करना

अगर आप useDeferredValue के अंदर कोई नया ऑब्जेक्ट या ऐरे हर रेंडर पर सीधे बना कर पास कर रहे हैं, जैसे:

const deferredValue = useDeferredValue({ query: text }); // गलत तरीका

तो यह हर रेंडर पर एक नया मेमोरी एड्रेस बनाएगा, जिससे React को लगेगा कि वैल्यू बदल गई है और वह ऑप्टिमाइज़ेशन को सही से नहीं चला पाएगा। हमेशा प्रिमिटिव वैल्यू (String, Number, Boolean) को ही पास करें या ऑब्जेक्ट्स को useMemo के साथ इस्तेमाल करें।

Toh dosto, humne aaj seekha...

आज के इस डिटेल्ड ट्यूटोरियल में हमने देखा कि React 18 का useDeferredValue Hook कैसे हमारी एप्लीकेशन की परफॉरमेंस को बूस्ट कर सकता है। हमने समझा कि कैसे यह भारी-भरकम कैलकुलेशन और लिस्ट रेंडरिंग को बैकग्राउंड में धकेल कर हमारे इनपुट फील्ड्स को सुपर-रिस्पॉन्सिव रखता है। बस याद रखें, इसका इस्तेमाल हर जगह नहीं करना है, बल्कि सिर्फ वहीं करना है जहाँ बहुत ज्यादा डेटा प्रोसेस हो रहा हो और यूजर को लैग महसूस हो रहा हो। इसे अपने प्रोजेक्ट में इम्प्लीमेंट करें और अपनी वेब ऐप्स को मक्खन की तरह स्मूथ बनाएं!

Frequently Asked Questions (FAQs)

Q1: क्या useDeferredValue हमारे API Requests को कम कर सकता है?
नहीं, useDeferredValue मुख्य रूप से ब्राउज़र के अंदर होने वाली रेंडरिंग और CPU-bound परफॉरमेंस को ऑप्टिमाइज़ करने के लिए है। अगर आप टाइपिंग पर होने वाली नेटवर्क API कॉल्स को कम करना चाहते हैं, तो आपको Debouncing का ही इस्तेमाल करना चाहिए।
Q2: React.memo का useDeferredValue के साथ उपयोग करना क्यों जरूरी है?
जब स्टेट बदलती है, तो पैरेंट कंपोनेंट तुरंत रेंडर होता है। अगर चाइल्ड कंपोनेंट React.memo से रैप नहीं होगा, तो वह भी तुरंत रेंडर हो जाएगा, जिससे useDeferredValue का बैकग्राउंड में रेंडर होने का उद्देश्य ही समाप्त हो जाएगा।
Q3: क्या useDeferredValue की वजह से UI पर पुरानी वैल्यू दिखाई देती है?
हाँ, बहुत ही कम समय (मिलीसेकंड्स) के लिए जब तक नया रेंडर बैकग्राउंड में पूरा नहीं हो जाता, तब तक यूजर को स्क्रीन पर पुराना डेटा दिखता है। आप "isStale" लॉजिक का उपयोग करके यूजर को एक हल्का स्पिनर या डिम इफ़ेक्ट दिखा सकते हैं।
Q4: useTransition और useDeferredValue में से कौन सा बेहतर है?
दोनों अपने-अपने स्थान पर बेहतरीन हैं। अगर आपके पास स्टेट चेंज फंक्शन (setSearch) का एक्सेस है तो useTransition बेहतर है। लेकिन अगर आपको पैरेंट से केवल रेडीमेड वैल्यू या प्रोप्स मिल रहे हैं, तो useDeferredValue ही एकमात्र और सबसे बढ़िया विकल्प है।
Q5: क्या useDeferredValue को हर इनपुट फील्ड में यूज़ करना चाहिए?
बिल्कुल नहीं! सामान्य फॉर्म इनपुट्स या छोटी लिस्ट्स में इसका उपयोग करने से ओवरहेड बढ़ सकता है। इसका उपयोग केवल तभी करें जब रेंडरिंग सचमुच बहुत हैवी हो और स्क्रीन लैग कर रही हो।
